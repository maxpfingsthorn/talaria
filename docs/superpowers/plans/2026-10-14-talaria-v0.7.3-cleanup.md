# Talaria v0.7.3 cleanup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the remaining parked review items (all but signed tags) in one release.

**Architecture:** Local fixes in existing modules. One optional op argument (`self-update --commit`), sent only to apps that announce v0.7.3 or later.

**Tech Stack:** Python ≥ 3.10 stdlib; pytest via uv; C for the e2e fake.

**Spec:** none separate — the parked findings are the spec; each task quotes its finding.

## Global Constraints

- Stdlib only; Python ≥ 3.10. Match surrounding style; comments only where the why is non-obvious. Existing `# pragma: no mutate …` stay unless their line is removed.
- No new `talaria.conf` / `hub.conf` keys; no accepted value may become refused. `PROTOCOL` stays 1. A v0.7.3 hub must keep driving v0.7.0–v0.7.2 apps, and a v0.7.2 hub must keep driving v0.7.3 apps.
- A login link must never reach stderr, the journal or a log line (including `ApiError` text).
- Public repo: placeholders only (`<host>.<tailnet>.ts.net`, `100.64.0.1`).
- Never run anything against the live host (`bin/talaria setup`, `sudo`, `systemctl`, `podman`, `tailscale`). Don't run e2e locally.
- Tests capped: `cd /home/max/talaria && timeout 600 systemd-run --user --scope -q -p MemoryMax=2G -p MemorySwapMax=0 uv run pytest -q -p no:cacheprovider tests --ignore=tests/e2e --ignore=tests/contract`.
- TDD: failing test first for every behaviour change.

## Review Focus

- `/update v<hub>` while one app is **ahead** of the hub must not downgrade that app — Task 1 test `test_retry_skips_an_app_ahead_of_the_hub`.
- `/status` with a flagged app that hangs answers within the short probe timeout and does not also call that app's `status` — Task 1 test `test_status_skips_a_hanging_flagged_app`.
- A v0.7.3 hub updating a v0.7.2 app must not send `--commit` (old argparse refuses it) — Task 2 test `test_update_sends_commit_only_to_apps_that_know_it`.
- A directory in the data dir swapped for a symlink during the rehearsal copy never pulls outside files into the copy — Task 3 test `test_copy_never_follows_a_dir_swapped_for_a_symlink`.
- Telegram timing out on the link's `sendMessage` neither logs the link nor leaves the owner without an expiry notice — Task 1 test `test_link_send_timeout_still_notifies_expiry`.

### Task 1: Hub and bot (items 6, 7, 8)

**Files:** `talaria/telegram.py`, `talaria/relay.py`, `talaria/hubcheck.py`, `talaria/hubupdate.py`; tests in `tests/test_telegram.py`, `tests/test_relay.py`, `tests/test_hubcheck.py`, `tests/test_hubupdate.py`.

**Item 8 — app ahead of the hub:** "An app newer than the hub gets a slightly odd update hint" (`send /update v<hub>`), and `relay.lagging` counts it as lagging, so `/update v<hub>` (the retry path in `hubupdate.offer`/`_self_update`) would self-update that app *down* to the hub's version.
- [ ] `relay.hello`: when the app's `version` is a string that is newer than `__version__` (`tags.semver_newer(f"v{v}", f"v{__version__}")`; tolerate non-semver strings — treat them as plain SKEW), return `AHEAD.format(ver=v)` with a new constant `AHEAD = "Talaria on this app (v{ver}) is newer than the hub's; /update v{ver} brings the hub up to it"`. Older or different-but-unparsable → `SKEW` as today.
- [ ] `lagging()` stays `startswith((VERSIONS, SKEW))` — AHEAD must not start with either (assert in a test). Bot `_lagging`/startup: an AHEAD app is neither in `mismatch` nor in `skewed`; `/status` shows its status plus `(AHEAD text)` like `with_skew` does (add `skew_note(text, note)` or extend the existing helper; keep `with_skew` output byte-identical).
- [ ] `hubcheck.check` timer reminder: for AHEAD send `f"{e.title}: {err}."` (no `/update v<hub>`); SKEW keeps today's text. AHEAD, like SKEW, still runs the app's check.
- Tests: `test_hello_reports_an_app_ahead`, `test_retry_skips_an_app_ahead_of_the_hub` (hub v0.7.3, app hello v0.7.4 and another app v0.7.2: retry offer and `_self_update` touch only the v0.7.2 app), reminder text for AHEAD.

**Item 7 — `/status` latency (v0.7.2 minor):** "`/status` can be slow (bounded at 60 s) while a lagging app hangs."
- [ ] `relay.hello(entry, timeout=60)`: pass `timeout` to `executor.call`. `Bot._lagging(timeout=60)` passes it through; `/status` calls `self._lagging(timeout=PROBE_TIMEOUT)` with `PROBE_TIMEOUT = 10`.
- [ ] When that re-probe answers `no_answer_text(...)` for an app, `/status` uses `"{title} did not answer in time"` for that app instead of calling its `status` (pass a `skip`/`texts` override into `relay.status_texts`, or build the dict in the bot; keep `status_all` output byte-identical).
- Tests: `test_status_skips_a_hanging_flagged_app` (fake executor raising `NoAnswer` on hello records the timeout it got = 10, and `status` is never called for that app).

**Item 6 — untracked login link (v0.7 minor):** "If Telegram delivers the link but our request times out, the bot doesn't record the message, so the expiry notice never replaces it."
- [ ] `Bot.send_link`: catch `ApiError`. `status == 0` (no HTTP answer: outcome unknown) → append `(due, None, title, app)` to `self.expiring`, print `f"[talaria] telegram sendMessage (login link for {app}): {e}"` to stderr (the `ApiError` text never contains params — keep it that way; assert the link is absent from stderr in the test). `status != 0` (Telegram refused) → `self.reply(f"Telegram refused the login link for {title} ({e}). Send /login {app} to try again.")`, nothing tracked.
- [ ] `expire_links`: for `mid is None`, send a new message `EXPIRED_UNSURE = "If a login link for {title} arrived, it has expired. Send /login {app} for a new one."` via `_try("sendMessage", …)`; otherwise edit as today.
- Tests: `test_link_send_timeout_still_notifies_expiry` (ApiError(0) on sendMessage → after LINK_TTL one new message with EXPIRED_UNSURE, no edit; captured stderr has no link), refused (ApiError(400)) → reply text, nothing tracked.

### Task 2: Pin the commit in self-update (item 3)

**Files:** `talaria/op.py`, `talaria/selfupdate.py`, `talaria/hubupdate.py`; tests in `tests/test_op.py`, `tests/test_selfupdate.py`, `tests/test_hubupdate.py`.

**Finding:** "Pinning the exact commit in self-update. This would mean passing the expected commit through `op self-update`." Today every install fetches the tag (forced) on its own; nothing ensures the hub and each app install the same commit.

- [ ] `op` parser: `s.add_argument("--commit", type=_commit)` where `_commit` accepts `^[0-9a-f]{40}$` only (argparse error otherwise). `_self_update` passes `commit=args.commit` to `selfupdate.self_update`. `--dry-run` ignores it.
- [ ] `selfupdate.self_update(ctx, tag, commit=None)`: after `fetch_tag`, if `commit`: `got = git rev-parse --verify -q f"refs/tags/{tag}^{{commit}}"`; if `got != commit` print `f"self-update refused: {tag} is {got[:12]} here, the hub installed {commit[:12]}"` to stderr and return 1 **before** checkout (nothing changed). Add `selfupdate.tag_commit(sh, install_dir, tag) -> str` for that rev-parse and reuse it in the hub.
- [ ] `hubupdate._self_update`: after the hub's own checkout (non-transitional, non-retry) take `pin = tag_commit(...)` of the hub install; in the retry or transitional path take `tag_commit` of the hub install if the tag exists there, else `None` (`CommandError` → `None`). `_update_app(entry, tag, pin)` adds `["--commit", pin]` only when `pin` and `relay.version(entry)` is a version `>= 0.7.3` (`FIRST_PIN_RELEASE = "v0.7.3"`; unknown/older → no flag). The final "installed" message gains ` (commit {pin[:12]})` when pinned.
- Tests: op rejects a non-hex/short commit; `test_self_update_refuses_a_different_commit` (no checkout call, rc 1); matching commit proceeds; `test_update_sends_commit_only_to_apps_that_know_it` (apps on 0.7.2 and 0.7.3: argv with/without `--commit`).

- [ ] Run the three test files, then the full suite. Commit "Self-update: hub pins the commit it installed for every app".

### Task 3: App side (items 2, 4, 5)

**Files:** `talaria/apps/gbrain.py`, `talaria/upstream.py`, `talaria/rehearse.py`, `talaria/safefs.py`; tests in `tests/test_gbrain.py`, `tests/test_apps.py` (or wherever `registry_tags` is tested — grep), `tests/test_rehearse.py`, `tests/test_safefs.py`.

**Item 2 — attestation fail-open (v0.6.1 finding):** "If gbrain's provenance check can't be completed, Talaria proceeds without recording that it happened."
- [ ] Keep proceeding (failing closed would stop every gbrain update for accounts without `gh`; setup already says so). In `GbrainApp.fetch`, add to the returned record `"provenance": "sha256+attestation"` when `gh attestation verify` ran and passed, else `"provenance": f"sha256 only ({why})"` with `why = attestation_unavailable(ctx)`.
- [ ] Surface it on every offer: `rehearse.candidate_message` (or gbrain's `report_lines`, whichever receives the fetch record — check how `image` reaches the report) adds the line `f"Build provenance not verified: {why}."` when the record's provenance starts with `"sha256 only"`. Records without the key (older state) add nothing.
- Tests: fetch with gh available → `sha256+attestation`; unavailable → `sha256 only (gh is not logged in for this account)` and the candidate message carries the line.

**Item 4 — Hermes tag listing (v0.6 finding):** "Hermes's list of release tags is read only up to 1000 entries." `podman search --list-tags --limit N` fetches every tag and then truncates to N (verified with podman 4.9.3: `--limit 100000` on an image with 4010 tags returns all 4010).
- [ ] `upstream.registry_tags`: `TAG_LIMIT = 100000`, pass it as `--limit`; if the parsed count reaches `TAG_LIMIT`, raise `ValueError(f"{image}: {TAG_LIMIT} or more tags; the list may be cut")` (check the caller's handling — a ValueError there must end as a check failure message, not a crash; adjust to the exception type the caller already maps if different).
- Tests: argv carries `100000`; a fake listing with TAG_LIMIT rows raises.

**Item 5 — rehearsal copy races (v0.6.1 finding):** "a symlink swapped in at directory level; a database file swapped for a special file at the last moment. Exploiting either needs a compromised container with exact timing."
- [ ] Replace `shutil.copytree` in `rehearse.copy_data` with an fd-based walk: open the root with `os.open(src, O_RDONLY|O_DIRECTORY|O_NOFOLLOW)`, list with `os.scandir(fd)`, descend with `os.open(name, O_RDONLY|O_DIRECTORY|O_NOFOLLOW, dir_fd=parent_fd)` (an `ELOOP`/`ENOTDIR` there = swapped → skip the entry, like a vanished file), copy files with a `safefs.copy_regular_at(dir_fd, name, dst)` variant that opens with `dir_fd` + `O_NOFOLLOW|O_NONBLOCK` (same checks as `copy_regular`), recreate symlinks as symlinks (`os.readlink(name, dir_fd=fd)`), keep the same skip rules (excludes, `-wal`/`-shm`, special files, vanished entries) and directory modes. Close every fd (try/finally).
- [ ] `_sqlite_copy`: before connecting, open `src` with `O_RDONLY|O_NOFOLLOW|O_NONBLOCK`, `fstat` → must be regular; after `backup`, `os.lstat(src)` must still have the same `(st_dev, st_ino)` and be regular, else delete `dst` and raise `OSError(f"{src} changed during the copy")`. Close the fd in `finally`. (sqlite opens by path; this detects a swap instead of preventing it — the rehearsal then fails as today's copy errors do.)
- Tests: `test_copy_never_follows_a_dir_swapped_for_a_symlink` (monkeypatch the walk so a subdir is replaced by a symlink to an outside dir after listing; no outside file appears in dst), existing copy tests still pass, `test_sqlite_copy_detects_a_swap` (swap src inode during backup via monkeypatched `sqlite3.Connection.backup` wrapper or by replacing the file before the post-check) raises and leaves no dst.

- [ ] Run the touched test files, then the full suite. Commit "App side: record unverified provenance, all registry tags, race-free rehearsal copy".
