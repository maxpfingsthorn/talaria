# Talaria v0.7.2 cleanup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close seven parked review items from v0.6.1/v0.7 in one small release.

**Architecture:** Local fixes in existing modules; no new modules, no new conf keys, no op protocol change.

**Tech Stack:** Python ≥ 3.10 stdlib; pytest via uv.

**Spec:** none separate — the parked findings are the spec; each task quotes its finding.

## Global Constraints

- Stdlib only; Python ≥ 3.10. Match surrounding style; comments only where the why is non-obvious. Existing `# pragma: no mutate …` stay unless their line is removed.
- No new `talaria.conf` / `hub.conf` keys. `PROTOCOL` stays 1. Existing op subcommands keep their arguments; a v0.7.2 hub must keep driving v0.7.x apps.
- A login link must never reach stderr, the journal or a log line.
- Public repo: placeholders only (`<host>.<tailnet>.ts.net`, `100.64.0.1`).
- Never run anything against the live host (`bin/talaria setup`, `sudo`, `systemctl`, `podman`, `tailscale`).
- Tests capped: `cd /home/max/talaria && timeout 600 systemd-run --user --scope -q -p MemoryMax=2G -p MemorySwapMax=0 uv run pytest -q -p no:cacheprovider tests --ignore=tests/e2e --ignore=tests/contract`.
- TDD: failing test first for every behaviour change.

## Review Focus

- A v0.6.0-era `talaria.conf` with an out-of-range but well-formed `tailscale_ip` during self-update — Task 2 test `test_render_accepts_any_ipv4_tailscale_ip`.
- A shell-unsafe `tailscale_ip` (`1.2.3.4;rm -rf ~`) still refused at render — Task 2 test `test_render_refuses_a_non_ipv4_tailscale_ip`.
- `/status` after an app caught up while the bot ran — Task 1 test `test_status_reprobes_flagged_apps`.
- Status text of an app on an older Talaria whose wording differs (no ", running.") — Task 1: no button, no crash.
- The operator install at a non-tag ref (a branch checkout during development) — Task 2 test `test_install_at_a_branch_still_fetches_tags`.

### Task 2: App side and setup (items 1, 3, 4, 6)

**Files:** `talaria/setup.py` (`_install` ~line 133), `talaria/units.py` (`render_quadlet` ~line 31), `talaria/conf.py` (`check_tailscale_ip` ~line 40), `talaria/rollback.py` (`describe` ~line 77), `talaria/apps/gbrain.py` (`login_link` fail text ~line 420), `talaria/cli.py` (`login_link`); tests in the matching `tests/test_*.py`.

Tests: `test_install_fetches_only_the_release_tag_forced` (argv contains the forced refspec, not `--tags`) and `test_install_at_a_branch_still_fetches_tags`.

**Item 3 — render guard during self-update (N4):** "the render-time `tailscale_ip` guard (`units.py:33`) … still runs during self-update. … a bad value now leaves the app lagging but usable."
- [ ] Split the check: add `conf.check_ipv4(value, where)` that accepts empty or any dotted IPv4 (`ipaddress.IPv4Address(value)` and `str(ip) == value`) and raises `ValueError(f"tailscale_ip must be an IPv4 address, got {value!r} in {where}")` otherwise. `render_quadlet` calls `check_ipv4` (shell safety: the value lands in an ExecStartPre shell line). `check_tailscale_ip` (100.64.0.0/10) stays where it is called today for strict setup validation — verify with grep that the strict path still calls it. Tests: `test_render_accepts_any_ipv4_tailscale_ip` (`192.0.2.7` renders), `test_render_refuses_a_non_ipv4_tailscale_ip` (`1.2.3.4;rm -rf ~` raises), and the existing strict-setup test for the range still passes.

**Item 4 — rollback "start it" offer names the skipped backup (N2):** "when `/rollback` offers to start the app instead of rolling back, the message doesn't name the backup it skipped."
- [ ] In `rollback.describe`, in the `needs_resume` branch, if `target(ctx, st)` returns a target `(bid, rec)` (guard with try/except like other callers if `target` can raise; read it first), append `f" Your data stays as it is. No target → message unchanged. Tests: both cases, exact text.

**Item 6 — terminal wording (v0.7 minor 5):** the terminal shows "details in the journal" right after printing the details.
- [ ] Keep gbrain's `LoginRefused` text for the bot. In `cli.login_link`, when the refusal text ends with `"; details in the journal"`, print it with that suffix replaced by `"; details above"`. Test in `tests/test_cli.py` with a gbrain ctx whose podman exec fails: stderr ends with `STOP: Could not get a login link from gbrain; details above`.
